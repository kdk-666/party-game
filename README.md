# 파티 게임

PC를 호스트 화면으로 사용하고, 참가자는 휴대폰으로 접속하는 웹 파티 게임입니다. 현재 무궁화 꽃이 피었습니다와 컬러헌트가 등록되어 있습니다.

## 게임 진행

- 참가자는 최대 4명입니다.
- 등록된 게임 중 최대 8개를 중복 없이 무작위로 선택합니다. 게임이 8개보다 적으면 등록된 게임만큼 진행합니다.
- 게임마다 설명과 준비 화면을 보여 줍니다. 전원 준비 시 바로 시작하고, 최대 60초가 지나면 자동으로 시작합니다.
- 게임 결과의 점수를 누적하고 다음 게임으로 이동합니다. 게임 사이에는 5초의 대기 시간이 있습니다.
- 대회 진행 중에는 새 참가자를 받지 않습니다.

## Docker로 실행하기

### 준비물

- Docker Desktop 및 Docker Compose
- 인터넷 연결: Python 이미지와 Cloudflare 터널 이미지를 내려받고 임시 접속 주소를 만드는 데 필요합니다.
- PC 브라우저와 카메라 및 센서를 사용할 수 있는 휴대폰 브라우저

### 실행

프로젝트 폴더에서 실행합니다. Windows에서는 Git Bash를 사용할 수 있습니다.

```bash
docker compose up --build
```

로그에 나타나는 `https://...trycloudflare.com` 주소를 PC 브라우저에서 엽니다. PC 화면의 QR 코드를 휴대폰으로 스캔해 참가합니다. 주소가 바로 나오지 않으면 터널 로그를 확인합니다.

```bash
docker compose logs tunnel
```

> 이 주소는 공개 인터넷을 통해 연결됩니다. 주소를 아는 사람은 접속할 수 있으므로 필요한 사람에게만 공유하고, 사용하지 않을 때는 종료하세요. 재실행 시 주소가 바뀔 수 있습니다.

호스트 PC에서 참가자를 확인하고 게임을 시작합니다. 휴대폰에서는 닉네임과 안내에 따라 필요한 권한을 허용하고 준비 버튼을 누릅니다. 카메라와 센서 권한, 기기별 HTTPS 및 브라우저 설정에 따라 사용 가능 여부가 달라질 수 있습니다.

실행 중인 터미널에서 `Ctrl+C`를 누르면 서비스를 중지할 수 있습니다. 종료 후 관련 컨테이너와 네트워크를 정리하려면 다음 명령을 실행합니다.

```bash
docker compose down
```

현재 Compose 설정은 호스트 PC에 8000번 포트를 직접 공개하지 않고 Cloudflare 터널을 사용합니다.

### 선택: 로컬 HTTPS 실행

`run.py`는 `mkcert`를 이용해 `certs/`에 로컬 인증서를 만들고 로컬 IP로 서버를 실행하는 별도 방법입니다. Docker 실행에는 필수가 아닙니다. 이 방법은 `mkcert` 설치와 기기별 인증서 신뢰 설정이 필요할 수 있습니다.

## 테스트

테스트 도구는 개발용입니다. Windows Git Bash에서 새 가상환경을 만드는 예시는 다음과 같습니다.

```bash
python -m venv .venv
./.venv/Scripts/python.exe -m pip install -r requirements-dev.txt
./.venv/Scripts/python.exe -m pytest -q
```

테스트에는 게임 규칙, 화면 파일 연결, 숨김 경로 차단 및 JavaScript 문법 검사가 포함됩니다. JavaScript 문법 검사는 Node.js가 있으면 실행되고, 없으면 해당 검사만 건너뜁니다. 테스트 통과만으로 실제 휴대폰 센서나 카메라 동작이 보장되지는 않으므로 실제 기기에서도 확인하세요.

## 폴더 구조

```text
games/
  red_light/          무궁화 게임 서버 코드, 설정, 전용 화면
  color_hunt/         컬러헌트 서버 코드, 설정, 전용 화면
server/
  games/registry.py   등록된 게임 목록
  game_pages.py       게임별 화면 파일 연결
  main.py             웹 서버와 WebSocket 처리
  match.py            게임 순서와 누적 점수
  preparation.py      설명·준비 화면의 상태 관리
web/
  host/               PC 공통 페이지
  player/             휴대폰 공통 페이지
  game-router.js      현재 게임에 화면 메시지 전달
  guide.* / lobby.*   공통 안내·대기 화면
  host-lobby.js       호스트 대기 화면 동작
tests/                개발용 테스트
```

각 게임의 `client/` 폴더에는 브라우저에 공개할 화면 코드와 이미지·음향 등의 게임 전용 리소스를 둡니다. 게임 규칙과 서버 전용 코드는 그 밖의 게임 폴더에 둡니다. `client/`와 `web/`의 일반 파일은 공개될 수 있으므로 비밀번호, 토큰, 개인 키 등은 넣지 마세요. 숨김 경로는 서버에서 차단합니다.

## 새 게임 추가하기

현재 구조는 자동 폴더 검색이 아니라 **명시적 등록 방식**입니다. 새 게임 폴더를 추가한 뒤 `server/games/registry.py`에도 등록하고 서버를 다시 빌드해야 합니다.

1. `games/<game_id>/`를 만들고 `game.py`, `manifest.py`, `client/` 등을 추가합니다. 게임 ID는 폴더 이름과 일치시키고 영문, 숫자, 밑줄 또는 하이픈을 사용합니다.
2. `game.py`에 게임 클래스를 구현합니다. 현재 서버는 `game_class(names, broadcast)`로 게임을 만들고 `async run()`을 호출합니다. 결과는 참가자 이름과 0 이상의 정수 점수가 담긴 `{"scores": {...}}`를 포함해야 합니다. 참가자 이탈을 처리할 `async remove_player(name)`도 필요합니다.
3. 현재 참가자 화면은 게임 종류와 관계없이 센서 값을 전송할 수 있습니다. 서버가 `game.on_motion(name, value)`를 호출하므로, 센서를 쓰지 않는 게임도 지금은 해당 비동기 메서드를 구현해 입력을 무시해야 합니다. 새로운 종류의 입력은 `server/main.py`의 WebSocket 처리에 추가 연결이 필요할 수 있습니다. 공통 입력 인터페이스는 아직 구현되지 않았습니다.
4. 각 게임이 시작할 때 공통 준비 화면을 닫기 위한 `countdown` 메시지와 시작 대기를 처리합니다. 기존 두 게임의 `game.py`를 참고하세요.
5. `manifest.py`에 `GAME_ID`와 `GAME_INFO`를 정의합니다. `GAME_INFO`에는 이름, 설명, 게임 클래스와 필요한 화면 설정을 넣습니다. 기존 `games/red_light/manifest.py`, `games/color_hunt/manifest.py`가 예시입니다.
6. 화면 파일은 `client/`에 두고 `ui` 설정의 `host`·`player`에서 각 스크립트 파일과 초기화 함수 이름을 지정합니다. 스타일은 `styles`에 지정합니다. 현재 이 설정에 적는 스크립트·스타일은 `client/` 바로 아래에 있는 단일 파일 이름이어야 합니다.
7. 초기화 함수는 `setup함수(ws, role, getName)` 형식으로 작성합니다. 라우터가 전달하는 `ws`는 전체 WebSocket 객체가 아니라 `send`, `readyState`, `addEventListener` 등을 제공하는 제한된 인터페이스입니다. `lobby`는 모든 게임 화면에 전달되며, 게임별 메시지는 현재 게임에 전달됩니다. 다른 게임으로 넘어갈 때 기존 화면은 `round_start`를 통해 정리 기회를 받으므로 타이머, 카메라, 소리와 화면을 정리해야 합니다.
8. `server/games/registry.py`에 새 게임의 ID와 설정을 가져와 등록합니다. HTML에 게임별 스크립트를 직접 추가할 필요는 없습니다.
9. 테스트를 추가·실행하고 Docker를 다시 빌드한 뒤, PC와 실제 휴대폰에서 게임 시작, 입력, 결과 및 다음 게임 전환을 확인합니다.

## 제출과 공유 시 주의사항

- `.idea/`, `.venv/`, 캐시 및 `certs/`는 제출용 소스에 넣지 않습니다. `certs/key.pem`은 개인 키이므로 공유하지 마세요.
- `.gitignore`와 `.dockerignore`는 각각 Git 추적과 Docker 빌드에서 불필요한 파일을 제외하는 설정입니다. 이미 Git에 추적 중인 파일은 `.gitignore`를 추가해도 자동으로 추적이 중단되지 않습니다.
- GitHub로 공유하려면 필요한 변경 사항을 커밋하고 올바른 브랜치에 푸시해야 합니다. 다른 브랜치에 있는 변경 사항은 기본 브랜치에 자동으로 반영되지 않습니다.
- ZIP으로 제출한다면 커밋된 파일만 `git archive`로 묶는 방법을 사용할 수 있습니다. **커밋하지 않은 변경 사항과 새 파일은 ZIP에 포함되지 않습니다.** 제출 전 브랜치와 ZIP 내용을 확인하세요.

```bash
git archive --format=zip --output=party-game-submit.zip HEAD
```

생성한 제출용 ZIP 자체는 소스 커밋에 포함하지 않도록 주의하세요.

## 추가 검토 사항

컬러헌트의 카메라 권한 응답 지연, 늦게 도착한 이전 회차 사진, 미제출자 점수 처리와 동점·이탈자 순위 정책은 추가 검토가 필요합니다. 현재 공통 입력 인터페이스와 게임별 센서 권한 분리도 향후 개선할 부분입니다.
